# Design: v1.5.0 — Web-Search Sourcing Guidance + HBO Max /shows/ URLs

**Date:** 2026-08-08
**Status:** Approved

## Goal

Fix two failure modes found while deep-linking "Bye Bye Birdie" from Brave Search
results, and rev the spec to v1.5.0:

1. The Prime Video regex matched a DVD product page
   (`amazon.com/dp/B0002V7TDI`) and extracted a retail ASIN that the Prime Video
   channel cannot play, while the real Prime Video page
   (`amazon.com/dp/B001G5RFHE`) sat lower in the results.
2. HBO Max's current URL scheme (`hbomax.com/shows/{slug}/{uuid}`) never matches
   the catalog regex, which only knows `/movies/`, `/series/`, `/video/watch/`,
   and `/play/` paths — so HBO Max content is silently unfindable from search.

## Key Findings (empirical, 2026-08-08)

- Prime Video titles and retail products share the `/dp/{ASIN}` URL shape;
  URL structure alone cannot distinguish them. Path-tightening the regex would
  break the good case: real Prime Video links surface as `/dp/` in search
  results.
- An unauthenticated `GET https://www.primevideo.com/detail/{asin}` (following
  redirects) returns **200 for video ASINs and 404 for retail ASINs**. Verified:
  B001G5RFHE → 200 ("Prime Video: Bye Bye Birdie"), B0DKTFF815 → 200,
  B0002V7TDI (DVD) → 404, B08N5WRWNW / B09B8V1LZ3 (Echo devices) → 404.
- Prefixing the search query with `watch` moves streaming pages above retail
  and placeholder pages (tested: Bye Bye Birdie — real Prime ASIN moved #5 → #1;
  Moana 2, The Marvelous Mrs. Maisel, The White Lotus — no regressions).
- primevideo.com search results use slug + GTI URLs
  (`/detail/{slug}/{GTI}`) that carry no ASIN — they are expected non-matches;
  the deep-linkable ASIN surfaces on the amazon.com `/dp/` result.
- Netflix serves `/title/{id}` pages for non-streamable catalog titles
  (e.g. `/title/342088`, a DVD-era placeholder). No URL-level or cheap
  HTTP-level discriminator was found (placeholder and playable pages both
  return 200 with equivalent markers). Documented as a known limitation; no
  mitigation in this rev (an ID-range heuristic was considered and rejected).

## Changes

### 1. HBO Max regex learns `/shows/` (catalog change)

```
(?:max\.com|hbomax\.com)/(?:(?:movies|series|shows)/[^/]+/(?:s\d+/)?|(?:video/watch|play)/)([^/?]+)
```

- Adds `shows` to the slug-prefixed alternative and an optional season segment
  (`s1/`), covering show pages (`/shows/white-lotus/{uuid}`), episode pages
  (`/shows/white-lotus/s1/{uuid}/e1-arrivals/28` — same show UUID), and
  sub-pages (`/shows/white-lotus/{uuid}/cast-and-crew` — capture stops at `/`).
- **Caveat:** deep-linking a `/shows/` page UUID has not been verified
  on-device yet (the spec already warns `/movie/{id}` IDs don't deep-link).
  The UUID is the same page-entity class as the long-standing `/series/`
  capture, so it is expected to behave the same.

### 2. Prime Video content-ID verification (new, recommended for search-sourced URLs)

Extraction stays pure and unchanged — `/dp/` fixtures still match. Verification
is a separate optional step, specified in the Prime Video channel details:

```
GET https://www.primevideo.com/detail/{content_id}    (no auth, follow redirects)
  200        → ASIN is a Prime Video title  → accept
  404        → ASIN is not a video (retail) → reject
  other/err  → indeterminate                → fail open (accept, log)
```

Only needed when the URL came from an untrusted source (web search) via an
ambiguous path: `/gp/video/` paths on amazon.com and all primevideo.com paths
are inherently video pages and skip the probe.

### 3. New SPEC.md section: "Sourcing URLs from Web Search" (consumer guidance)

Appended as §11 (no renumbering of existing sections). Contents:

- Query shaping: `watch {title} {site: filters}` — one `site:` clause per
  public domain in the catalog.
- Candidate iteration rule: a candidate rejected by verification MUST NOT
  satisfy or block its channel — keep scanning lower-ranked results so a
  later legit candidate can claim it.
- The Prime Video probe (cross-ref to the catalog entry).
- Optional result-title ranking hint ("Watch {title} | Prime Video" vs
  "Amazon.com: {title} : …"). Ranking only, never sole grounds for rejection.
- Known limitation: Netflix placeholder `/title/` pages.

Consumers without web-search sourcing (e.g. roku-mcp) ignore §11 entirely.
